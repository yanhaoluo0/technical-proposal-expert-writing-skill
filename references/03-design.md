# 03 设计阶段

先读 [../writing-guidelines.md](../writing-guidelines.md)。需求编号规则若已存在于 SRS，设计文档必须沿用，禁止另起一套。

## 功能设计说明书

**模板**：`文档示例/03 设计阶段/功能设计说明书 - 模板.docx`

### 大纲

1. 文档介绍（五节）
2. 系统概述
   - 2.1 系统说明
   - 2.2 项目背景
   - 2.3 系统任务
3. 需求说明
   - 3.1 整体需求
   - 3.2 功能需求（含 需求编号规则、总体模块划分）
4. 功能性需求（按模块；表结构同需求规格说明书）
5. 界面设计
   - 5.1 界面的功能（前台界面 / 后台界面）
   - 5.2 界面关系（页面 1…n）

### 界面关系每页必写

- 页面名称
- 页面说明（入口、主要操作、跳转）
- 与功能编号的对应（「见图 / 见功能 xxx」）

不要只贴「见图」而无页面说明。没有线框图时用结构描述（区域：导航 / 列表 / 表单 / 操作），并标明「待确认（需补界面稿）」。

### 检查清单

- [ ] 编号规则与 SRS 一致（若无 SRS，在 3.2.1 新建并声明）
- [ ] 第 4 章模块表 + 功能描述
- [ ] 第 5 章区分前台/后台，页面有说明与功能对应
- [ ] 未把本文写成接口文档而丢掉界面章

**模板**：`文档示例/03 设计阶段/数据库设计说明书 - 模板.docx`

### 大纲

1. 文档介绍（五节）
2. 数据库环境说明
   - 2.1 数据库系统（产品与版本，未知则「待确认」）
   - 2.2 设计工具
   - 2.3 数据库配置
3. 数据库的命名规则
   - 3.1 数据表名称规范
   - 3.2 数据项名称规范
   - 3.3 数据表结构定义（约定字段顺序与必填元数据）
4. 数据库设计
   - 4.1 逻辑设计（实体、关系、说明）
   - 4.2 物理设计（表、索引、约束）

在 3.1 / 3.2 写明前缀、大小写、分隔符。例如：`t_` 表、`idx_` 索引；字段 `snake_case`。选定后全文遵守。
