# 02 需求规格说明书

先读 [../writing-guidelines.md](../writing-guidelines.md)。

**模板**：`文档示例/02 需求阶段/需求规格说明书 - 模板.docx`  
**示例**：`文档示例/02 需求阶段/需求规格说明书 - 示例.docx`

## 大纲（不得改成通用 SRS）

1. 文档介绍（五节）
2. 项目介绍
   - 2.1 项目说明
   - 2.2 项目背景
   - 2.3 项目目标
   - 2.4 项目用户
3. 需求说明
   - 3.1 整体需求
   - 3.2 功能需求
     - 3.2.1 需求编号规则
     - 3.2.2 总体模块划分
4. 功能性需求（按模块展开）

不要擅自加「非功能需求」大章来替换第 4 章。若用户给了性能/安全/接口需求，放在 3.1 整体需求，或在对应模块的功能描述里写可验证指标。

## 编号规则（先写规则，再写功能）

在 3.2.1 **先**给出规则，后文所有编号必须符合它。推荐（与示例一致，可按项目缩写替换）：

```
{项目或系统缩写}{模块缩写}{三位序号}
子功能 = 父编号 + 三位序号
```

示例：`xxdt001`（地图模块第 1 项），`xxyw001001`（业务模块第 1 项的第 1 个子功能）。

规则节必须写清：缩写对照、序号宽度、是否允许插入号（如 001a）。没有规则就列出功能 = 不合格。

## 总体模块划分表

每个模块一张（列名固定）：

| 模块名称 | （填写） |
|---|---|
| 模块简介 | （填写） |

模块功能列表：

| 序号 | 一级功能-功能名称 | 一级功能-功能编号 | 二级功能-功能名称 | 二级功能-功能编号 |
|---|---|---|---|---|
| 1 |  |  |  |  |

无二级功能时，二级列留空，不要删列。

## 第 4 章写法

- 章下按模块编号设 `4.x {模块编号或模块名}`
- 每个一级功能一节，二级功能作小节
- 每个功能至少包含：功能编号、功能名称、功能描述（谁在什么前置条件下做什么、结果是什么）
- 需要界面或规则时补：输入、处理、输出、约束、异常
- 功能名、编号必须与第 3 章模块表一致

### 功能描述句式

> 【角色】在【前置条件】下，能够【动作】，系统【结果】。不满足【约束】时，系统【异常处理】。

禁止只写「该功能用于某某」而不写角色和结果。

## 检查清单

- [ ] 封面 + 变更履历 + 文档介绍五节
- [ ] 3.2.1 有完整编号规则
- [ ] 每个模块有划分表，列名未改
- [ ] 第 4 章编号与第 3 章一致，无孤儿功能、无重复编号
- [ ] 功能描述含角色、动作、结果
- [ ] 未编造接口字段或指标；未知写「待确认」
