# 06 验收阶段

先读 [../writing-guidelines.md](../writing-guidelines.md)。

## 系统竣工报告

**模板**：`文档示例/06 验收阶段/01 系统竣工报告/系统竣工报告 - 模板.docx`

### 大纲

1. 概要 — 项目是什么、为谁建设、当前状态
2. 项目开发 — 实际完成的功能范围（尽量引用需求编号）
3. 硬件 — 实际使用的硬件/部署环境；无硬件也要写「无独立硬件，部署于……」
4. 测试 — 测试结论，引用测试报告，不编造通过率
5. 培训 — 对象、时间、材料；未做则写「待确认 / 未开展」
6. 提交成果（表）

| 序号 | 成果名称 |
|---|---|
| 1 |  |

7. 附件
   - 7.1 用户签字
   - 7.2 项目经理签字

签字未知时保留小节并写「待签」。

## 安装维护手册

**模板**：`文档示例/06 验收阶段/02 安装维护手册/安装维护手册 - 模板.docx`

### 大纲（按模板；环境不同时改产品名，不要删章）

1. 引言
   - 1.1 编写目的
   - 1.2 软件背景
2. 操作系统安装
   - 2.1 硬件环境
   - 2.2 Linux 系统安装（准备工作 / 安装过程）
3. Oracle 数据库安装（前期准备 / 安装流程）  
   若实际不是 Oracle：保留「数据库安装」章，标题改为实际库，并在 1.2 声明与模板差异
4. 项目应用部署
   - 4.1 WEB 应用程序发布（JDK / Tomcat / Web 部署；栈不同则替换为实际栈，步骤仍要可执行）
   - 4.2 数据库部署
   - 4.3 系统部署信息汇总
5. 系统管理员平台维护
   - 数据字典、组织机构、用户管理、工作分配、基础数据维护、用户注册审批

步骤按「操作 → 预期结果」写。密码用占位符。

## 培训文档

**模板**：`文档示例/06 验收阶段/03 培训文档/培训文档 - 模板.pptx`

默认产出 Markdown 提纲（一页一个 `##`），用户要 PPT 再套模板。建议页序：

1. 封面（项目名、培训对象、日期）
2. 培训目标与议程
3. 系统背景与角色
4. 核心业务流程
5. 分角色操作演示（每角色至少 1 条主路径）
6. 常见问题与注意事项
7. 练习 / 考核（若有）
8. 联系人与材料清单

## 使用手册

**模板**：`文档示例/06 验收阶段/04 使用手册/使用手册 - 模板.docx`（模板仅为标题层级占位）

仍要封面 + 变更履历 + 文档介绍五节，然后按用户角色组织操作章节：

```
1. 文档介绍
2. 系统简介与登录
3. {角色A}操作（每节：入口、步骤、结果、异常）
4. {角色B}操作
5. 常见问题
```

每条操作使用：

> 路径：【菜单】→【页面】  
> 步骤：1. … 2. …  
> 结果：…  
> 异常：…

不要写成设计说明书口吻（「本模块采用……架构」）。

## 检查清单

- [ ] 竣工报告七章 + 成果表 + 签字小节
- [ ] 安装手册步骤可执行，无真实密码
- [ ] 使用手册按角色/路径写，不按开发模块堆砌术语
- [ ] 培训材料有对象和议程
