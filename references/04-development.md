# 04 系统提测申请单

先读 [../writing-guidelines.md](../writing-guidelines.md) 的术语与禁止编造条款。本文是表格，无「文档介绍」五节。

**模板**：`文档示例/04 开发阶段/系统提测申请单 - 模板.xlsx`（表名：系统提测申请单）

## 表头字段

项目名称、项目经理、提测人、提测日期、测试类型。

测试类型按用户给定填写（如功能测试 / 回归 / 冒烟）；未知则「待确认」。

## 提测系统明细（一行一个变更）

列名固定：

| 序号 | 模块编号 | 子模块编号 | 功能变化说明 | 变化类型 | 功能描述 | 负责人 | 影响分析 | 测试重点 | 注意事项 |
|---|---|---|---|---|---|---|---|---|---|
| 1 |  |  |  |  |  |  |  |  |  |

- 模块编号 / 子模块编号与 SRS 或功能设计一致
- 变化类型写清楚：新增 / 修改 / 删除 / 修复
- 影响分析不能留空（至少写影响范围：模块、数据、接口）
- 测试重点给测试可执行的点，不要写「请全面测试」

## 升级与交付

另写三块（模板中有对应栏）：

1. **升级步骤**：有序列表（步骤 1、步骤 2…），能让测试按步骤部署
2. **提供文件**：程序 / 脚本 / 相关文档，列出实际文件名或「待确认」
3. **测试相关说明**：环境、账号、数据准备、已知问题

## 检查清单

- [ ] 表头五字段在
- [ ] 每一行有模块编号与变化类型
- [ ] 有升级步骤，不是「按常规发布」
- [ ] 未编造提测日期；未知写「待确认」
