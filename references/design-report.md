# 方案设计报告

与 SKILL.md 通用书写要求同时生效。仅在匹配到本场景后读取。

适用于技术方案设计报告、系统/软件研制方案设计说明。每章先写清「谁在什么环节用」，再写技术，避免空泛。语气专业；正文叙述为主。层级用 `1`、`1.1`、`1.1.1`。指标、接口、清单可用表。

标题可按项目改名（模块名、技术点名、风险点名），**章序不要擅自合并或删掉**，没有的内容写「本节不适用：…」或「待确认」。

## 大纲

**1 概述**

- 1.1 任务来源：立项背景、下达方、合同/项目来源、要解决的问题
- 1.2 功能用途：功能、服务对象、典型场景与使用环节
- 1.3 研制依据：标准、规范、上级文件或合同条款（不编造文号）
- 1.4 引用文件
- 1.5 术语与缩略语

**2 功能以及技术指标**

- 2.1 总体要求
- 2.2 软件要求（OS、运行环境、依赖与版本）
- 2.3 硬件要求（服务器、终端、网络、存储；可给典型配置）
- 2.4 其他指标（可用性、容量、并发、响应、兼容；与 1.2 场景对应，能量化则量化）

**3 总体方案**

- 3.1 总体设计原则
- 3.2 应用场景（使用方、环节、流程、与周边系统）
- 3.3 总体设计
  - 3.3.1 系统总体架构
  - 3.3.2 系统组成
  - 3.3.3 系统工作流程
  - 3.3.4 数据库设计方案
  - 对外接口可放 3.3 或第 4 章，须写清对接对象与使用场景

**4 分模块的技术方案**

- 4.1 总体功能明细（模块与功能点对照表）
- 4.2 起按实际模块设节。每模块包含：职责、场景中的位置、关键流程、接口与数据依赖、与指标/需求的对应

**5 关键技术以及解决处理途径**

按实际技术点设 5.1、5.2…。每节：难点或目标、方案与依据、算法/内核思路、实现要点与效果、对应场景或指标。

**6 通用特性设计**

- 6.1 可靠性
- 6.2 安全性
- 6.3 维护性
- 6.4 测试性
- 6.5 保障性
- 6.6 适配性

**7 管理措施**

- 7.1 项目团队管理
- 7.2 研制风险与解决措施（7.2.1 起按风险项：描述、影响、对策、责任）

**8 交付清单**

- 8.1 设备交付清单（表）
- 8.2 资料交付清单（表；可注明使用/运维场景）

**9 研制生产进度安排**

阶段、里程碑、节点与产出；联调、试运行写入进度。可用表 + 短叙述。

**10 指标符合性**

对照第 2 章逐条或分类说明如何满足，引用章节号。禁止在无设计依据时写「完全满足」。

**11 结论**

要点、已响应的需求与指标、主要风险与对策、后续建议。

**附录（按需）**：修订记录；术语表（1.5 已写则不重复）；接口或配置项清单。

## 输出

每次完整一章或一节（如整章「3 总体方案」或「4.2 某模块」）。约每 1000 个中文字符暂停确认。文件增量追加。

## 匹配后说明

已匹配方案设计报告，按 1–11 章骨架写，并扣住场景与使用细节。请补充项目名称、提纲或拟先写的章节，以及任务来源、使用方。
