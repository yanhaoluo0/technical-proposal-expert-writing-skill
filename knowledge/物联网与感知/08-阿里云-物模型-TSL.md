## 1. 适用场景与触发词

需要「在阿里云 IoT 平台定义设备功能模型（属性 / 服务 / 事件）+ 设备按统一模型通信」时命中本卡片：

- 业务场景：阿里云 IoT 平台上的产品定义、设备接入、命令下发、事件订阅
- 标书或设计报告关键词：「物模型」「TSL」「Thing Specification Language」「属性」「服务」「事件」「阿里云物联网平台」「IoT 平台」

## 2. 技术内涵与边界

**做什么**：

- 阿里云物联网平台为产品定义的数据模型；描述产品的功能
- 从属性、服务、事件三个维度描述设备「是什么」「能做什么」「可对外提供哪些信息」
- 支持多组功能定义（即「物模型模块」）——一个产品下不同设备可实现不同功能
- 通过 TSL（Thing Specification Language）描述物模型模块与功能
- TSL 文件为 JSON 格式

**不做什么**：

- 不替代设备 SDK——物模型是产品定义，设备 SDK 用于设备端实现
- 不替代消息中间件——设备与云端通信仍走 MQTT / CoAP
- 不擅长跨厂商互操作——物模型是阿里云特有的抽象
- 不擅长实时流处理——属性上报 / 事件触发后流转给业务系统

## 3. 典型架构与关键机制

### 3.1 三大维度定义

> 官方原文：「物模型是物理空间中的实体（如传感器、车载装置、楼宇、工厂等）在云端的数字化表示，从属性、服务和事件三个维度，分别描述了该实体是什么、能做什么、可以对外提供哪些信息。定义了物模型的这三个维度，即完成了产品功能的定义。」

| 功能类型 | 说明 |
|---|---|
| **属性（Property）** | 描述设备运行时具体信息和状态（如环境温度、智能灯开关状态、电风扇风力等级）；分读写和只读 |
| **服务（Service）** | 设备可供外部调用的指令或方法；输入输出参数；分同步 / 异步 |
| **事件（Event）** | 设备主动上报的信息（任务完成通知、故障告警）；可包含多个输出参数；可被订阅和推送 |

### 3.2 物模型模块

> 官方原文：「物联网平台支持为产品定义多组功能（属性、服务和事件）。一组功能定义的集合，就是一个物模型模块。多个物模型模块，彼此互不影响。物模型模块功能，解决了工业场景中复杂的设备建模，便于在同一产品下，开发不同功能的设备。」

- 一个产品可定义多个模块
- 同一产品下不同设备可使用不同模块
- 例：电暖扇「电源开关」「档位」在一个模块，「室内温度」在另一个模块
- 默认模块 + 自定义模块总数 ≤ 200 个
- **2021 年 1 月 1 日（不含当日）之前已定义的产品功能**，归类于默认模块

### 3.3 TSL（Thing Specification Language）

> 官方原文：「物联网平台通过定义一种物的描述语言来描述物模型模块和功能，称为 TSL（Thing Specification Language）。」

- TSL 文件 = JSON 格式
- 物模型模块下功能可只含属性 / 服务 / 事件，无需三者都有
- 在 IoT 平台控制台「产品详情 > 功能定义 > 物模型 TSL」可查看或导出 JSON

### 3.4 TSL 单文件 / 多文件

| 方式 | 限制 |
|---|---|
| 单个 TSL 文件 | `.json` 后缀；合法 JSON；文件大小 ≤ 512 KB；有效字符 ≤ 256 KB（256 × 1024 个字符）；有效字符指 JSON 格式中除换行和对齐字符外的字符 |
| 多个 TSL 文件（批量） | 压缩为 `.zip`；文件大小 ≤ 2.5 MB；可正常解压；压缩包内至少 1 个有效物模型文件，最多 1 个默认模块物模型文件 + 9 个自定义模块物模型文件；多个自定义物模型文件的 `functionBlockName` 与 `functionBlockId` 不可重复 |

### 3.5 设备通信

设备使用物模型通信（基于 MQTT / CoAP）：

- 属性上报：设备 → 云
- 属性设置：云 → 设备
- 服务调用：云 → 设备
- 事件上报：设备 → 云

### 3.6 物模型数据校验

- 平台按 TSL 定义校验上报 / 下发的属性值、参数值
- 字段类型、取值范围、字符串长度等

### 3.7 产品与设备关系

- 一个「产品」= 一个物模型
- 一个产品下可有多个「设备」（Thing）
- 每个设备对应一个 DeviceShadow / 物模型实例

## 4. 关键设计决策与权衡

### 决策 1：阿里云 IoT 平台 vs AWS IoT Core vs Azure IoT Hub

- **阿里云 IoT 平台（本方案阿里云生态 + 国产化场景采用）**：物模型 TSL 抽象；与阿里云其他服务深度集成
- **AWS IoT Core**：Device Shadow；MQTT 主题
- **Azure IoT Hub**：Device Twin；多协议
- **代价**：跨云迁移物模型需重新设计；TSL 是阿里云特有抽象

### 决策 2：单模块 vs 多模块

- **单模块（简单产品）**：所有功能在同一模块
- **多模块（复杂产品 / 子型号）**：按功能域拆分
- **代价**：模块过多增加管理复杂度；按业务边界划分

### 决策 3：TSL 编写方式

- **控制台单个添加（原型 / 小规模）**：UI 交互式
- **批量导入 TSL（产品化 / 标准化）**：JSON / ZIP 批量
- **代价**：批量导入需保证 JSON 合法；模块命名 / ID 唯一

### 决策 4：属性读写类型

- **只读属性**：设备主动上报（如传感器读数）
- **读写属性**：云端可下发配置（如阈值、模式）
- **代价**：读写属性需云端设计「谁有权限写」的授权模型

## 5. 工程化要点

- **产品创建**：在 IoT 平台控制台「设备管理 > 产品」创建产品；选择品类、节点类型、联网方式
- **物模型设计**：
  - 按业务域拆模块
  - 属性命名规范化（建议按层级命名）
  - 数据类型（int / float / double / text / bool / enum / struct / array）
- **TSL 编写**：
  - 优先批量导入（JSON / ZIP）
  - 控制台校验
  - 版本管理（变更记录）
- **设备端**：
  - 设备 SDK（Link SDK / 自研）
  - 设备按物模型属性 / 服务 / 事件映射实现
- **服务端**：
  - IoT 平台开放 API
  - AMQP / MQTT 订阅设备消息
  - 业务规则引擎（阿里云物联网平台规则引擎）
- **监控**：
  - 设备上下线
  - 消息流转
  - 物模型调用成功率

## 7. 标书化叙述示例

> 本方案基于阿里云物联网平台构建 IoT 产品体系。平台选型：阿里云 IoT 平台（含物模型 TSL）。产品定义采用物模型三维度——属性（设备运行状态）、服务（设备可调用指令）、事件（设备主动上报信息），按业务域拆分为多个物模型模块。TSL 文件以 JSON 格式维护，单个 TSL 文件大小 ≤ 512 KB，多模块批量导入时压缩为 `.zip`（≤ 2.5 MB）。设备端使用阿里云 Link SDK（C / Java / Python）实现，按物模型映射设备功能。属性读写按业务类型选择——传感器读数设为只读，云端下发配置设为读写；事件触发后通过 IoT 平台规则引擎流转至 Kafka / 函数计算 / 数据库。服务端通过 IoT 平台开放 API + AMQP / MQTT 订阅消费设备消息；设备上下线、消息流转、物模型调用成功率通过 IoT 平台监控。具体业务的设备规模、物模型模块数、消息频率由用户在合同附件中按业务等级明确。

## 8. 风险与边界

- **不可编造项**：
  - TSL 文件大小、批量导入限制等具体数字必须以阿里云 IoT 平台官方文档为准
  - 阿里云 IoT 平台各版本特性差异（如新增功能、字段）需回到官方文档核对
- **常见失败模式**：
  - TSL JSON 不合法 → 批量导入失败；先本地校验
  - 模块 ID / Name 重复 → 导入失败；命名规范化
  - 物模型调用频率超限 → 平台 Rate Limit；按业务削峰
  - 设备 SDK 版本不兼容 → 升级 SDK
  - 跨产品迁移 → 重新定义物模型
- **架构外延**：本卡片聚焦物模型 TSL；不涵盖阿里云 LinkKit / Link SDK、IoT 平台规则引擎、IoT 设备身份认证、边缘网关（LinkEdge）
